# Agent Instructions for ocx-tools

This package provides TypeScript types, JSON schemas, and validators for the K-12 OCX (Open Content Exchange) specification.

## Project Structure

```
ocx-tools/
├── src/
│   ├── bin/                  # CLI programs
│   ├── formats/              # Format-specific validators (lmsActivity, etc.)
│   ├── index.ts              # Main exports
│   ├── ocx.d.ts              # Auto-generated OCX entity TS types
│   ├── ocx.schema.json       # Auto-generated OCX entity JSON Schema
│   ├── manifest.d.ts         # Manifest types (manual)
│   ├── manifest.schema.json  # Manifest JSON Schema (manual)
│   └── validation/           # AJV, Ark, manifest and package validation
├── test/                     # Vitest tests
├── └── fixtures/             # Test fixtures
├── ontology/                 # Source data for schema generation
│   ├── entities.json         # Entity definitions
│   ├── extensions.json       # Extensions (new entities and entity property extensions)
│   └── value_standards.json  # Enum definitions
└── scripts/                  # Code generation scripts
```

## Key Commands

```bash
npm test              # Run tests with Vitest
npm run typecheck     # TypeScript type checking
npm run lint          # Biome linter
npm run lint:fix      # Auto-fix lint issues
npm run build         # Build to dist/
npm run clean         # Delete dist/ folder
npm run generate-schema  # Regenerate schemas from ontology
```

## Code Generation

Files marked "Auto-generated" are generated from `ontology/` files:
- `src/ocx.d.ts` - Generated by `scripts/generateSchema.ts`
- `src/ocx.schema.json` - Generated by `scripts/generateSchema.ts`
- `src/validation/ark.ts` - Generated by `scripts/generateArkTypes.ts`

Do not edit these files directly. Modify the ontology files and run `npm run generate-schema`.

## Extensions

The `ontology/extensions.json` file allows extending the OCX schema without modifying the core `entities.json`. It supports two mechanisms:

### Adding New Entities

Add new entity definitions to the `entities` array:

```json
{
  "entities": [
    {
      "entity": "NewEntity",
      "label": "New Entity",
      "definition": "Description of the entity.",
      "properties": {
        "identifier": { "type": "String", "cardinality": "1", ... }
      }
    }
  ]
}
```

### Extending Existing Entities

Add or override properties on existing entities via `entityExtensions`:

```json
{
  "entityExtensions": {
    "Lesson": {
      "hasPart": {
        "description": "Updated description...",
        "type": ["Activity", "Material"],
        "cardinality": "0..n"
      }
    }
  }
}
```

This merges with the base entity definition during schema generation. Use this to:
- Add new relationship types (e.g., `Lesson->hasPart->Material`)
- Add new properties to existing entities
- Override property definitions (type, cardinality, description)

After modifying `extensions.json`, run `npm run generate-schema` to regenerate the schema files.

## Testing

Tests use Vitest. Test files mirror source structure in `test/`. Fixtures are in `fixtures/`.

## CLI Tool

The package provides a CLI tool for validating OCX files and packages:

```bash
# Validate OCX JSON files
ocx-validate course.ocx.json lesson.ocx.json

# Validate OCX packages (.ocx.zip)
ocx-validate curriculum.ocx.zip

# Validate with reference checking
ocx-validate --check-references curriculum.ocx.zip

# Validate Representation content (e.g., lmsActivity files)
ocx-validate --validate-content curriculum.ocx.zip

# Output as JSON
ocx-validate --json course.ocx.json
```

## Dependencies

- `@zip.js/zip.js` - ZIP file handling for package validation
- `semver` - Version range checking for manifest format
- `ajv` and `arktype` are optional peer dependencies for validation
